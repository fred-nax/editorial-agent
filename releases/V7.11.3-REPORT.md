Les scripts `releases/deploy-v7*-remote.sh` **abortent** si le dossier est détecté dans la source ou l’image — conserver ces gardes pour tout futur déploiement.

### 6.6 Précautions obligatoires — futures migrations VPS

Avant **tout** `prisma migrate deploy` sur un VPS / base prod :

1. **Artefact = Git uniquement** (clone tag, archive `git archive`, image Docker buildée depuis CI/Git). Interdit : rsync / copie du working tree développeur.
2. **Préflight drop GEO** sur l’artefact et dans le conteneur :
   - `test ! -d prisma/migrations/20261103173400_drop_ai_visibility_monitor`
   - `git ls-files prisma/migrations | grep drop_ai` → vide (si `.git` présent)
3. **Préflight base cible** (lecture seule) :
   - Les 7 tables `Visibility*` **présentes** (attendu prod historique)
   - `_prisma_migrations` **sans** l’entrée `20261103173400_drop_ai_visibility_monitor`
4. **Dump** complet avant migrate ; fenêtre de maintenance courte.
5. Appliquer **uniquement** les migrations absentes (V7.11.x additives si pas encore déployées) — **jamais** réintroduire ni résoudre (`migrate resolve`) le drop GEO.
6. Conserver les abort des scripts `deploy-v7*-remote.sh` ; les répliquer pour V7.12.0+.
7. Après migrate : recompter tables métier + `Visibility*` = 7 ; confirmer qu’aucune ligne drop n’a été ajoutée à `_prisma_migrations`.

**Interdit :** `migrate reset`, `migrate deploy` depuis un laptop avec le dossier drop local, `prisma db push` destructif, restauration d’un dump local (sans GEO) sur prod.

## 7. Préparation inventaire Webflow (V7.12.0) — audit seulement

### 7.1 Modèle actuel

- `WordPressPost` : `@@unique([workspaceId, wpPostId])`, champs WP (`slug`, `status` libre, `contentType` post/page, `categories` Json).
- `WordPressSyncRun` : cycle running/completed/failed, mode full/incremental, diagnostics.
- Binding workspace ajouté en V7.11.1 (backfill WP).

### 7.2 Couche d’accès

- Routes sync : auth + `resolveActiveWorkspace` + `assertWordPressOnlyModule` + filtre runs.
- **Écart moteur :** `lib/seo/wordpress-inventory.ts` hard-code `WORKSPACE_IDS.wordpress` dans upsert/count/cursor ; ignore `run.workspaceId`.
- Credentials : `resolveWordPressConfig()` → `AppSettings` global ; variable module `syncWpCredentials` non sûre en concurrence multi-espace.
- `inventory-guard` : validité / count **globaux**.

### 7.3 Sync / dédup / pagination / erreurs / publish vs draft

| Mécanisme | Comportement |
|-----------|--------------|
| Sync | Fire-and-forget in-process ; 409 si run `running` ; upsert only (pas de purge locale) |
| Dédup | Mémoire `contentType:id` + unique DB `(workspaceId, wpPostId)` |
| Pagination | `per_page=100`, headers `X-WP-Total*` — **spécifique WP** (Webflow = offset/limit) |
| Erreurs | Retry ×3 ; `rest_forbidden_status` skip ; run `failed` ; **pas** de recovery stale-`running` |
| Publish/draft | `publish` via `context=view` ; drafts posts via `context=edit` ; pages souvent skip drafts |

### 7.4 Mutualisable vs CMS-spécifique

**Réutilisable :** couche `lib/workspace/*`, cycle SyncRun + polling 202/409, upsert non destructif, diagnostics `byStatus`, invalidation origin/validité (à scoper), pattern de tests.

**WP-only :** REST `wp/v2`, Basic auth, `modified_after`, headers Total, vocabulaire de statuts, `fetchWordPressNoRedirect`.

**Webflow à concevoir :** collections/items, `isDraft`/`isArchived`/`lastPublished`, mapping `fieldData`, rate-limit 429, credentials par `WorkspaceCmsSettings`, modèle `WebflowItem` **ou** `CmsContentItem` générique (décision ouverte).

### 7.5 Recommandations techniques V7.12.0

1. Paramétrer le moteur d’inventaire sur `run.workspaceId` + credentials workspace (supprimer hard-code WP).
2. Scoper `inventory-guard` et abandonner le count global.
3. Ajouter recovery des runs `running` orphelins.
4. Introduire un modèle Webflow dédié (éviter de surcharger `WordPressPost`).
5. Garder empty states honnêtes : **jamais** réutiliser l’inventaire WP en compensation.
6. Avant déploiement VPS : vérifier présence des 7 tables GEO et **absence** de l’entrée drop dans `_prisma_migrations` ; s’assurer que l’artefact ne contient pas le dossier drop.

Fichiers clés : `lib/seo/wordpress-inventory.ts`, `lib/seo/wordpress-url.ts`, `app/api/wordpress-inventory/sync/**`, `lib/workspace/*`, `lib/webflow/*`, `lib/cms/webflow-connector.ts`, `lib/settings/inventory-guard.ts`.

## 8. Risques résiduels

1. **AppSettings / WorkspaceCmsSettings** — écriture settings encore globale ; dual-read masque l’écart.
2. **Inventaire WP hard-codé** — bloque un second espace WP et la mutualisation V7.12.0.
3. **Stats GSC/GA4** — colonnes `workspaceId` nullable ; upserts sans ownership fiable ; clés uniques hors workspace.
4. **Header binding optionnel** — plusieurs mutations UI n’envoient pas encore `x-naxialis-workspace-id`.
5. **Dossier drop GEO local gitignoré** — piège `migrate deploy` hors Git.
6. **Maillage / similarité / titles** — défauts WP acceptables tant qu’un seul inventaire WP existe.
7. **OAuth Google unique** — disconnect WP coupe Google pour toute l’app (by design Phase A) ; désormais refusé depuis Webflow.
