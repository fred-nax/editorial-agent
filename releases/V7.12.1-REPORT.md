## 1. Synthèse

Activation des **rapprochements éditoriaux** et du **maillage interne** pour l’espace Webflow, en réutilisant les moteurs lexicaux WordPress existants et `listEditorialInventory`.

- WordPress : comportement historique préservé (URL obligatoire, `status: publish`, prompt dynamique inchangé).
- Webflow : inventaire local uniquement (drafts inclus pour doublons) ; maillage uniquement si `published` + `isLive` + URL http(s) confirmée.
- Aucune instruction permanente d’agent modifiée.
- Aucun fallback inventaire WordPress → Webflow.
- Opportunités SEO Webflow / images Webflow : **non développés**.

## 2. Règles de maillage Webflow

| Condition | Obligatoire |
|-----------|-------------|
| Même `workspaceId` | Oui |
| `status = published` | Oui |
| `isLive = true` | Oui |
| URL publique `http(s)` connue | Oui |
| Pertinence sujet (score local) | Oui |

**Exclus :** brouillons, archivés, missing, URL absente/non vérifiée, items WordPress, versions staged non live.

Si live indisponible **et** aucune URL fiable → **aucun** lien proposé (jamais d’URL inventée).

État actuel Studio : site non publié → catalogue maillage vide (attendu).

## 3. Doublons / rapprochements

| Source | Usage |
|--------|--------|
| Inventaire Webflow (`purpose: duplicates`) | Titres, slugs, extraits, contentText, drafts inclus |
| File éditoriale (topics) | Sujets non archivés du même espace |
| Générations Webflow | Dédupliquées vs `cmsExternalId` inventaire |

- Analyse **locale** (pas d’appel OpenAI sur le chemin principal).
- Bouton IA WordPress conservé ; **non exposé** sur Webflow.
- Similarité lexicale **jamais** présentée comme cannibalisation SEO.
- FR/EN : stop words anglais enrichis ; détection titres/slugs EN vérifiée.
