# Rapport V7.16.4 — Auth.js HTTPS Middleware Hotfix

**Statut :** validation technique **locale** terminée — **aucun** commit / tag / push / déploiement VPS.  
**Baseline :** `v7.16.3` · `7976cc57191ef301fcf6651ab6f4397ac5eacbe2`  
**Diagnostic :** `docs/operations/OPS-03A-AUTH-REGRESSION.md`

---

## 1. Cause racine

`middleware.ts` (AUTH-003, V7.16.1+) appelait :

```ts
getToken({ req, secret })
```

Sans `secureCookie`, `@auth/core` utilise `secureCookie ?? false` → cookie `authjs.session-token` et salt associé.  
En production HTTPS (`AUTH_URL=https://…`), Auth.js émet `__Secure-authjs.session-token`.  
Derrière nginx-proxy (TLS terminé, upstream HTTP), le middleware ne lisait pas le cookie → **faux 401** « Non authentifié. » sur toutes les API privées, alors que `auth()` RSC fonctionnait.

---

## 2. Correctif (périmètre hotfix)

| Fichier | Rôle |
|---------|------|
| `lib/auth/secure-cookie.ts` | `resolveSecureSessionCookie()` — priorité `AUTH_URL` / `NEXTAUTH_URL` |
| `middleware.ts` | Passe `secureCookie` (+ `nodeEnv`) à `getToken` |
| `tests/middleware-secure-cookie-v7164.test.ts` | Tokens Auth.js réels + contrats |
| `docker-compose.validate-https.yml` | Stack isolée proxy HTTPS |
| `scripts/ops/validate-https/nginx.conf` | Proxy de validation |
| `scripts/ops/ops03a-validate-https.{sh,mjs}` | Recette login + API |

**Hors scope :** CMS, éditorial, agents OpenAI, migrations PG, Google tokens, nginx VPS.

### Règles `secureCookie`

1. `AUTH_URL`/`NEXTAUTH_URL` `https://` → **toujours** Secure (ignore XFF falsifié `http`)  
2. URL `http://` → non-Secure (dev local)  
3. Sans URL : protocole requête https **ou** XFF `https` → Secure  
4. `NODE_ENV=production` sans AUTH_URL → Secure (pas de fallback permissif)  
5. Salt = cookieName (défaut Auth.js) — chunks SessionStore inchangés  

Auth.js installé : `next-auth@5.0.0-beta.32` · cookies session : `__Secure-authjs.session-token` / `authjs.session-token` · **pas** de cookies Auth.js personnalisés dans `auth.ts`.
