## 2. Architecture retenue

Réutilisation du pattern Webflow V7.13.1, adapté aux **IDs numériques WordPress** :

| Couche | Rôle |
|--------|------|
| `WordPressCmsReference` | Catalogue workspace-scopé (category \| author), soft-missing |
| `Topic` + `editorialContext` | Choix figés (`wpCategorizationMode`, `wpCategoryIds`, `wpAuthorId`) |
| `WorkspaceCmsSettings` + `AppSettings` | Mode / défauts / capacité auteur (dual-write) |
| APIs `/api/wordpress-references*` | Sync + catalogue + défauts |
| `/api/articles/[id]/wordpress-references` | Lecture / PATCH brouillon distant ciblé |
| Injection serveur | `run-session` → `createDraft({ categoryIds, authorId? })` hors schéma outil |

**Non modifié :** instructions permanentes agent, signature `create_wordpress_draft`, `resolveCategoriesForSubject` en mode automatique.

## 3. Mode automatique historique

## 4. Mode manuel

- UI formulaire + file : **Métadonnées éditoriales WordPress**.
- Remplace entièrement la détection automatique.
- Sélection multi-catégories validée en recette.
- Sélection vide → `categories: []` (défaut / Uncategorized WordPress).
- Validation serveur avant OpenAI ; pas de repli silencieux vers l’automatique.

---

## 5. Permissions auteur WordPress

Probe lecture seule (`/users/me`, `/users?who=authors` si autorisé).

| Capacité | Comportement |
|----------|--------------|
| `self_only` / `can_list_authors` | Compte API seul (rôle Auteur CDC) |
| `can_assign` | Autre auteur sélectionnable ; `author` injecté si ≠ API |
| `unknown` | Compte API conservé |

Aucune élévation de permissions · aucune modification d’utilisateurs WP.
