## 1. Architecture retenue

Réutilisation du moteur SEO WordPress existant (`processOpportunitySearch`, scoring, thématiques, configs, file) avec **activation de module** et **adaptateurs CMS** :

| Couche | Choix |
|--------|--------|
| Données | Aucune migration — `SeoOpportunity` / `CustomTheme` / `ResearchConfig` déjà `workspaceId` |
| Gate | `"opportunities"` ajouté à `WEBFLOW_ENABLED_MODULES` |
| Inventaire préflight | `countWorkspaceInventoryForOpportunities` (WP posts vs Webflow items) |
| Doublons | `findSimilarContent` branche sur `cmsProvider` ; Webflow via `listEditorialInventory(purpose: "duplicates")` + générations + opportunités déjà enregistrées |
| Google | **Non branché** pour Webflow ; jamais de GSC/GA WordPress en fallback |
| Langue | `EditorialWorkspace.defaultLanguage` injectée dans les prompts dynamiques uniquement |
| UI | Même `OpportunitiesBoard` ; sync inventaire CMS-aware (`/api/webflow-inventory/sync` vs WP) |

Aucun changement des instructions permanentes des agents OpenAI ni des connecteurs CMS de génération.

## 6. Correctif recette (ArticleGeneration.angle)

### Diagnostic
- **Service :** `findSimilarWebflowInventory` dans `lib/seo/duplicates.ts` (appelé par `findSimilarContent` pendant `processOpportunitySearch`).
- **Cause :** `select: { angle: true }` sur `ArticleGeneration` — le champ **n’existe pas** ; l’angle est dans `editorialContext` (JSON).
- **Run échoué :** `cmww7761200065cax2y9cc10f` — `foundCount: 0`, aucune opportunité Webflow créée.
- **OpenAI :** l’appel `web_search` a **très probablement** eu lieu **avant** l’échec Prisma (doublons après candidats). Aucune relance automatique.
- **Données conservées :** WP **119**, Webflow **5**, thématiques Webflow **6**.

### Correction
- Select Prisma : `editorialContext` ; angle via `parseStoredEditorialContext` (null si absent).
- Messages UI : `toPublicOpportunitySearchError` — plus d’erreur Prisma brute ; détail technique en logs.
- Message du run échoué sanitizé en base (même enregistrement, pas de suppression).

### Pourquoi les 623 tests précédents n’ont pas vu l’erreur
1. La majorité des tests V7.12.2 sont **source / lexicaux** (grep, similarité locale) — **pas** d’exécution Prisma `articleGeneration.findMany` Webflow.
2. Aucun test d’intégration n’appelait `findSimilarContent(…, ws_webflow)` contre une vraie base avant ce correctif.
3. Le typecheck n’a pas bloqué le select invalide dans le flux précédent (client / chemin non exercé au build des tests) — désormais couvert par un test Prisma migtest.

### Nouveau test
- `tests/webflow-opportunities-prisma-v7122.test.ts` — requêtes Prisma réelles sur migtest, générations avec/sans angle, inventaire Webflow, workflow post-OpenAI simulé, conversion file, sanitisation erreurs.

## 8. Risques résiduels

1. Une recherche réelle consomme OpenAI (`web_search`) — coût possible si une étape locale échoue ensuite.
2. URLs Webflow souvent nulles → rapprochements sans lien cliquable (attendu).
3. Lexique similarité encore partiellement FR-centric pour les intentions métier.

## 9. Amélioration future (non livrée)

**Valider les prérequis PostgreSQL / Prisma avant tout appel OpenAI payant** dans le workflow de recherche d’opportunités (ex. dry-run de la requête `articleGeneration` / inventaire scopé), afin d’éviter une consommation `web_search` si une étape locale est déjà invalide.
