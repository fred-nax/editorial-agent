## 2. Cause exacte de l’absence des coûts

### Chaîne auditée

Réponses Agents / usage session → `collectSessionUsage` → `estimateLlmCostUsd(model, tokens)` → persistance `ArticleGeneration.estimatedCost` → dashboard / historique / détail / KPI mensuel (filtrés par `workspaceId`).

### Cause racine

Le référentiel `lib/openai-pricing.ts` ne contenait que **`gpt-5.6-terra`**.

L’agent Webflow renvoie le modèle **`gpt-5.6-sol`**. Sans tarif → `estimateLlmCostUsd` retourne **`null`** → UI « — » / coût vide, alors que **tokens + modèle étaient bien enregistrés**.

Ce n’était **pas** uniquement un bug d’affichage (`formatEstimatedCost` V7.13.0 était correct pour les montants connus).

### Autres constats (partiel / hors scope automatisé)

| Élément | Statut |
|---------|--------|
| Input / cached / output / reasoning | OK — cached ⊆ input, reasoning ⊆ output (pas de double comptage) |
| `web_search` | Hors estimation LLM (pas de fee tool persistée) |
| Images `gpt-image-2.5-flare` | Tarif token connu OpenAI, **mais aucune consommation image persistée** sur `ArticleFeaturedImage` → coûts image absents du total génération |
| Isolation workspace | OK (agrégats dashboard scopés) |

## 6. Proposition technique — sélecteurs WordPress (non implémentée)

### Audit du fonctionnement actuel

| Élément | Comportement réel |
|---------|-------------------|
| Agent WP | Outils `web_search` + `create_wordpress_draft` (signature inchangée) |
| Catégories | Résolues **côté serveur** avant/pendant la session via `resolveCategoriesForSubject` (`lib/wordpress-categories.ts`) — mapping Naxialis legacy **ou** liste autorisée sync + défaut ; injectées dans `categoryIds` du connecteur, **pas** choisies par le LLM dans le schéma outil |
| Auteur | **Non sélectionnable** : le brouillon REST utilise le compte authentifié (`wpUsername` / app password) — pas de champ `author` dans le payload |
| Formulaire / file | Pas de sélecteurs catégorie/auteur WP (contrairement à Webflow V7.13.1) |
| Sync | Catégories WP déjà synchronisées (`WorkspaceCmsSettings.wpCategoriesJson`, UI Paramètres éditoriaux) |

### Modes proposés (après votre GO)

**Mode automatique (défaut — zéro régression)**  
- Conservé tel quel : détection serveur + défauts existants.  
- Auteur = compte API actuel.

**Mode manuel**  
- Sélecteurs UI réutilisant le pattern `WebflowRefsFields` mais branchés sur le catalogue WP déjà sync (`SyncedWpCategory` + auteurs via `GET /wp/v2/users?who=authors` ou endpoint existant si présent).  
- Persistance file : champs Topic dédiés (ex. `wpCategoryIds`, `wpAuthorId`) **ou** réutilisation contrôlée de `category` textuelle — préférer IDs numériques typés.  
- Figés dans `editorialContext` / options `run-session` comme pour Webflow.  
- Validation serveur avant OpenAI (IDs ∈ allowed + origin cohérente).  
- Injection : remplacer `categoryIds` détectés par la sélection manuelle **sans** changer le schéma `create_wordpress_draft` (toujours injecté hors outil).  
- Auteur manuel : ajouter `author` au payload REST WordPress uniquement si permissions OK ; sinon message explicite.

### Non-objectifs de cette proposition

- Pas de modification des instructions permanentes agent.  
- Pas de signature outil OpenAI changée.  
- Pas d’implémentation avant validation de cette proposition.
