## 8. Correctif layout UX (post-intégration sélecteur)

### Cause exacte

Sur `components/Sidebar.tsx`, la classe Tailwind `relative` avait été ajoutée à l’`<aside>` déjà `fixed` (pour positionner le dropdown collapsed). En Tailwind v4, `relative` et `fixed` ont la même spécificité : `relative` gagne dans la feuille CSS générée.

Conséquence : la sidebar **quittait le positionnement fixe** et **rentrait dans le flux document**, ce qui :
- poussait le header / le contenu sous la hauteur de la sidebar ;
- créait l’énorme espace vide au-dessus du Dashboard ;
- donnait l’impression d’une « ligne » indépendante pour la sidebar.

Comparaison `v7.11.1` : l’aside n’avait que `fixed inset-y-0 … lg:flex` — sans `relative`.

### Correctifs

1. Retrait de `relative` sur l’aside (`fixed` restauré, comme v7.11.1).
2. `relative` limité aux wrappers internes du `WorkspaceSelector` (dropdowns).
3. Libellés sélecteur sans répétition :
   - ligne 1 : **WordPress** / **Webflow** ;
   - ligne 2 : domaine / label site (`naxialis.com`, `Naxialis AI Studio 01`) ;
   - icône CMS + chevron.
4. Même logique sur `ActiveWorkspaceIndicator`.

### Vérification géométrique (CDP navigateur, serveur `:4000`)

| Viewport | asideTop | headerTop | headerLeft ≈ asideWidth | OK |
|----------|---------:|----------:|------------------------:|:--:|
| 1920×1080 | 0 | 0 | 240 | oui |
| 1440×900 | 0 | 0 | 240 | oui |
| 1280×800 | 0 | 0 | 240 | oui |
| 1280 collapsed | 0 | 0 | 72 | oui |
| 390×844 | aside `display:none` | 0 | 0 | oui |
