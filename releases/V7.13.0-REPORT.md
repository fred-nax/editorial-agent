## 1. Architecture retenue

Réutilisation du **moteur d’images OpenAI WordPress** (prompt, style, format, génération, ALT, optimisation, stockage local, locks) avec un **connecteur Webflow Assets + association staged** dédié :

| Couche | Choix |
|--------|--------|
| Génération | `lib/images/service.ts` mutualisé ; prompt **sans** identité / données WordPress pour les générations Webflow |
| Transfert | `lib/webflow/assets.ts` — POST métadonnées `/sites/{id}/assets` → upload S3 `uploadUrl` **sans** token Webflow |
| Association | `lib/webflow/featured-image-attach.ts` — PATCH item staged uniquement ; mapping dynamique `featured_image` / `alt_text` |
| Persistance | Colonnes additives `webflowAssetId`, `webflowAssetUrl`, `cmsTransferStatus` (wpMedia* inchangés) |
| Gate | Module `featured_image` activé pour Webflow ; routes via `resolveFeaturedImageWorkspace` |
| UI | Onglet Image réactivé pour Webflow ; design WordPress conservé ; transfert explicite + reprise association |

**Jamais :** endpoints live / publish / unpublish ; création d’asset pour sonder les permissions ; token Webflow vers S3 ; URL d’upload fournie par le navigateur.

## 5. Gestion des erreurs et reprises

| Étape | Statut / `cmsTransferStatus` |
|-------|------------------------------|
| Générée / optimisée | `ready` |
| Asset créé + fichier uploadé | `file_uploaded` + `webflowAssetId` |
| Associée au brouillon | `attached` / `associated` |
| Échec après upload | `ready` + `association_failed` (asset conservé) |
| Échec avant upload | `failed` |

- Reprise association **sans** régénération OpenAI ni nouvel asset si IDs présents.
- Lock `upload-webflow:{generationId}` anti concurrence.
- Refus publié / archivé / statut incertain.
- Pas de suppression automatique d’assets Webflow.

## 8. Finalisation — coûts USD

### Cause identifiée
`formatEstimatedCost` (`lib/format.ts`) affichait un format fr-FR (`0,175 $`) et **masquait** les montants `< 0,01` sous la chaîne opaque « `< 0,01 $` ». Les données `ArticleGeneration.estimatedCost` étaient toujours présentes en base pour WordPress (ex. `0.17508`).

### Correctif
Format préfixe `$` avec précision adaptative :

| Cas | Affichage |
|-----|-----------|
| `null` / NaN | `—` (inconnu) |
| `0` | `$0.00` |
| `\|x\| < 1` | 4 décimales (`$0.0024`, `$0.0450`, `$0.1248`) |
| `\|x\| ≥ 1` | 2 décimales (`$1.25`) |

Moteur `estimateLlmCostUsd` / tarifs **non modifiés**. Aucune invention de coûts manquants.

### Limitation observée
Les générations Webflow actuelles (`model: gpt-5.6-sol`) ont des tokens mais `estimatedCost = null` car le modèle n’a pas d’entrée dans `MODEL_RATES` (seul `gpt-5.6-terra` est tarifé). Affichage correct : `—`. Pas d’ajout de tarif dans cette finalisation.

Les coûts d’image (prompt / génération image) ne sont **pas** persistés séparément sur `ArticleGeneration` — hors scope de cette restauration d’affichage.

- Coûts Webflow `gpt-5.6-sol` absents tant que le modèle n’a pas de tarif officiel dans `openai-pricing.ts`.
- Coûts image non ventilés dans `estimatedCost` article.
