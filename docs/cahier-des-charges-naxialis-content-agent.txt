Projet : Naxialis Content Agent
Version : 1.0
Date : 02/10/2026

==================================================
1. CONTEXTE DU PROJET
==================================================

Naxialis dispose déjà d’un agent éditorial OpenAI capable de :
- rechercher des informations récentes et fiables ;
- rédiger des articles de blog orientés SEO et intention commerciale ;
- produire un contenu HTML structuré ;
- générer les champs SEO nécessaires à Slim SEO ;
- détecter les catégories WordPress pertinentes ;
- générer des tableaux HTML stylés avec Tailwind ;
- générer une FAQ en accordéons natifs <details>/<summary> ;
- créer automatiquement un brouillon dans WordPress via l’API REST ;
- ne jamais publier automatiquement un article.

Le script actuel fonctionne en local en Node.js et se lance depuis la ligne de commande avec un sujet d’article.

Exemple :
node index.mjs "Comment utiliser un agent IA pour automatiser les tâches répétitives d’une PME ?"

L’objectif du présent projet est de transformer ce fonctionnement en une application web privée, simple à utiliser et accessible en ligne, réservée à Naxialis.

L’application ne remplace pas l’agent existant : elle sert de tableau de bord pour le piloter, suivre les générations, gérer une file éditoriale et centraliser l’historique.

==================================================
2. OBJECTIFS PRINCIPAUX
==================================================

L’application doit permettre de :

1. saisir un sujet d’article depuis une interface web ;
2. lancer la génération de l’article avec l’agent OpenAI existant ;
3. suivre visuellement l’état d’avancement de la génération ;
4. créer le brouillon dans WordPress via le mécanisme existant ;
5. afficher le résultat de la génération ;
6. afficher l’identifiant du brouillon WordPress créé ;
7. fournir un lien direct vers le brouillon ou son édition WordPress ;
8. enregistrer un historique des générations ;
9. gérer une file de sujets à traiter ;
10. afficher les principales métadonnées de chaque génération ;
11. conserver toutes les clés API et identifiants côté serveur ;
12. protéger l’application par authentification ;
13. permettre un déploiement Docker sur un VPS privé.

==================================================
9. GÉNÉRATION D’UN ARTICLE
==================================================

L’utilisateur saisit un sujet.

Exemple :
"Comment automatiser les tâches répétitives d’une PME avec un agent IA ?"

Lorsqu’il clique sur "Générer l’article" :

1. l’application crée un enregistrement en base avec le statut pending ou queued ;
2. le statut passe à running ;
3. l’application appelle l’agent OpenAI existant ;
4. l’agent effectue ses recherches ;
5. l’agent rédige l’article ;
6. l’agent appelle la fonction create_wordpress_draft ;
7. l’application crée le brouillon WordPress via l’API REST ;
8. le résultat du tool call est retourné à l’agent ;
9. l’agent termine la session ;
10. l’application enregistre le résultat ;
11. le statut passe à completed ;
12. l’interface affiche l’ID WordPress et le lien vers le brouillon.

En cas d’erreur :
- statut failed ;
- message d’erreur stocké ;
- erreur affichée proprement dans l’interface ;
- possibilité de relancer ultérieurement.

==================================================
11. INTÉGRATION OPENAI
==================================================

L’application doit reprendre la logique du script Node.js existant.

L’agent OpenAI existant doit rester la source de vérité éditoriale.

L’application ne doit pas dupliquer inutilement toutes les instructions de l’agent.

Le prompt dynamique doit rester court.

Exemple :

Crée un article complet pour le blog Naxialis sur :
"{subject}"

Applique toutes tes règles éditoriales et SEO, puis crée le brouillon WordPress.

L’application doit :
- créer une session avec l’agent ;
- écouter les événements de session ;
- gérer les événements requires_action ;
- exécuter create_wordpress_draft ;
- transmettre le tool_result ;
- récupérer le résultat final ;
- stocker les informations pertinentes en base.

19. SÉCURITÉ
==================================================

Toutes les clés et secrets doivent rester côté serveur.

Ne jamais exposer dans le navigateur :
- OPENAI_API_KEY ;
- WP_APP_PASSWORD ;
- DATABASE_URL ;
- AUTH_SECRET ;
- mot de passe administrateur.

Aucune variable sensible ne doit utiliser le préfixe NEXT_PUBLIC_.

Prévoir :
- HTTPS obligatoire en production ;
- validation des entrées ;
- protection des routes API ;
- limitation des erreurs détaillées côté client ;
- logs serveur ;
- secrets via variables d’environnement ;
- .env exclu de Git ;
- contrôle des permissions WordPress ;
- utilisateur WordPress dédié à l’application.

Option future :
- rate limiting ;
- 2FA ;
- restriction IP ;
- authentification via reverse proxy.

23. GESTION DES ERREURS
==================================================

L’application doit gérer proprement :
- erreur OpenAI ;
- erreur de session agent ;
- erreur de tool call ;
- erreur WordPress REST API ;
- authentification WordPress invalide ;
- expiration ou erreur réseau ;
- erreur PostgreSQL ;
- génération interrompue.

Une erreur ne doit pas laisser une génération indéfiniment en statut running.

Prévoir un message exploitable côté interface.

Exemples :
- "Erreur OpenAI pendant la génération" ;
- "Impossible de créer le brouillon WordPress" ;
- "Authentification WordPress refusée".

Les détails techniques complets restent dans les logs serveur.

24. DÉPLOIEMENT
==================================================

L’application doit pouvoir être déployée via Docker Compose.

Services minimum :
- app Next.js ;
- PostgreSQL.

Exemple :

services:
  app:
    build: .
    restart: unless-stopped
    env_file:
      - .env
    depends_on:
      - db

  db:
    image: postgres:16-alpine
    restart: unless-stopped
    environment:
      POSTGRES_DB: naxialis_agent
      POSTGRES_USER: naxialis
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
    volumes:
      - postgres_data:/var/lib/postgresql/data

volumes:
  postgres_data:

L’application pourra être exposée via un sous-domaine du type :
- agent.naxialis.com ;
- content.naxialis.com.

HTTPS obligatoire.
