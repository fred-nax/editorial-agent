# V7.5 — Catalogue unifié des thématiques SEO

## Architecture retenue

- **Une seule table** : `CustomTheme` devient le catalogue administrable.
- Les cinq domaines historiques de `EDITORIAL_DOMAINS` (`lib/seo/domains.ts`) restent la **source de seed**, plus la source runtime exclusive.
- `SeoOpportunity.theme` (string) est **conservé** ; `themeId` (FK nullable) est ajouté progressivement.
- Aucune création automatique de thématiques depuis WordPress ou l’IA.

## Migration

Fichier : `prisma/migrations/20261113120000_seo_themes_catalog_v75/migration.sql`

Strictement additive :

- colonnes `CustomTheme` : `legacyKey`, `explorationAngles`, `defaultQuota`, `sortOrder`, `naxialisServices`
- colonne `SeoOpportunity.themeId` + index + FK `ON DELETE SET NULL`

### Seed / backfill

```bash
npx prisma migrate deploy
npm run seo:seed-themes
```

Au démarrage applicatif, `ensureHistoricalEditorialThemes()` (via `lib/boot.ts`) :

1. si `legacyKey` existe → skip
2. si nom homonyme sans `legacyKey` → attache seulement `legacyKey` (**pas d’écrasement**)
3. sinon → crée la thématique historique

`backfillOpportunityThemeIds()` rattache les opportunités historiques par label (script seed uniquement, pas au boot).

## Rollback applicatif

1. Revenir au code précédent.
2. Laisser les colonnes additives en base (inoffensives).
3. Ne pas exécuter de `DROP` en production.
4. Ne jamais restaurer `20261103173400_drop_ai_visibility_monitor`.
